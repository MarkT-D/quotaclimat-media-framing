What is Next.js?

Next.js is a React framework — it adds routing, a build system, server rendering, and API routes on top of React. You don't need a separate Express server.

App Router (used here)

Every folder under app/ with a page.tsx becomes a URL. A folder named article/[id] creates a dynamic route where [id] is a URL parameter.

KEY
app/overview/page.tsx → localhost:3000/overview. The app/layout.tsx wraps every page with the shared header — it runs once for the whole session, not per navigation.

Server vs Client Components

TypeDefault?Can doCannot do
Server ComponentYes (App Router default)Query DB directly, read env vars, fetch on serveruseState, onClick, browser APIs
Client ComponentNo — add "use client" at topuseState, useEffect, event handlers, browser APIsDirect DB access
HERE
Almost every file here starts with "use client". The dashboard is highly interactive (charts, filters, hover states) so it all runs in the browser. The only server-side code is api/articles/route.ts, which queries Postgres.

Files named route.ts inside app/api/ become HTTP endpoints. They export async functions named GET, POST, etc.

Turbopack (dev mode)

INFO
npm run dev uses --turbopack — a Rust-based bundler replacing Webpack. Much faster hot-reload. Production builds still use the standard Next.js compiler.

Why Next.js here?

What it replaces
A separate Express server for the API + a separate Vite/CRA setup for the frontend. One repo, one dev command.
The tradeoff
More conventions to learn (file-based routing, server/client boundary), but zero config for common patterns.

Why PostgreSQL?

PostgreSQL is an open-source relational database. Data is stored in tables with typed columns; you query it with SQL.

Why relational (not MongoDB/Firebase)?

Structured schema
Every article has the same columns. A relational DB enforces this. A document DB allows inconsistent shapes — that adds bugs when you compute aggregations.
Cheap aggregation
Counting articles by sector, averaging frame scores per outlet — cheap single-table SQL queries. A document DB would need map-reduce or in-app loops.
JSONB escape hatch
explanation_frames / explanation_angles are JSONB — variable-shape attention maps live inside the relational table without a schema migration.
Transactions
An article upload writes all columns atomically. If it fails partway, Postgres rolls back the whole insert.

How the project queries it

INFO
The postgres npm package (not Prisma, not pg) is used. Tagged template literals: sql`SELECT * FROM articles WHERE id = ${id}` — values are automatically parameterised, preventing SQL injection. Connection pool (max 10) is a module singleton in lib/db.ts.

Why Docker?

Docker packages software into a container — an isolated environment with its own filesystem, network, and process space that runs identically on every machine.

The docker-compose setup

services:
  db:
    image: postgres:16           # exact Postgres version, reproducible
    environment:
      POSTGRES_USER: quota
      POSTGRES_PASSWORD: changeme
      POSTGRES_DB: quota_climate
    ports:
      - "5432:5432"              # host:container — localhost:5432 → Postgres
    volumes:
      - pgdata:/var/lib/postgresql/data  # data persists across restarts
Why not install Postgres directly?
No version conflicts across machines. One command starts and stops it. Data lives in a Docker volume, not scattered across the host filesystem.
The volume
docker compose down stops the container but data persists. docker compose down -v destroys the volume — full reset. Re-seed with the .sql dump file.

Connection string

DATABASE_URL=postgresql://quota:changeme@localhost:5432/quota_climate
#                         user:password @host       :port/dbname
NOTE
@localhost works because Docker maps port 5432 from the container to the host's localhost. Both Next.js and the Python backend connect to localhost:5432.

FastAPI & Python Backend

FastAPI is a modern Python web framework with automatic OpenAPI docs and Pydantic validation. It runs separately from Next.js on port 8000.

Why a separate Python server?

KEY
The BERT models are PyTorch. PyTorch runs in Python. You cannot run a PyTorch model inside a Node.js process — they're different runtimes. So ML inference lives in Python and Next.js calls it over HTTP.

Lazy model loading pattern

# NOT loaded at import time.
# Loaded lazily on first call, with a lock to prevent double-load.
_predictor = None
_load_lock = threading.Lock()

def _get_predictor():
    global _predictor
    if _predictor is not None: return _predictor
    with _load_lock:
        if _predictor is not None: return _predictor  # double-check
        _predictor = Predictor(checkpoint_path=_checkpoint)
        return _predictor
WHY
Loading BERT weights takes ~5–10 seconds. The lifespan context manager starts loading in a background thread so GET /health responds immediately. If checkpoint directory doesn't exist, /classify returns HTTP 503 gracefully.

Platt scaling calibration

CALIBRATIONS = {
    "Conflict": {"W": 1.0098, "b": -0.1047},
    ...
}
# Applied as: calibrated_score = sigmoid(W * raw_logit + b)
WHY
Raw BERT softmax probabilities are often poorly calibrated (e.g. always outputs 0.9). Platt scaling fits a linear function on a validation set so "80% confident" actually means 80% accuracy. The angle model has no calibration yet.

lib/db.ts

9 lines. Creates a shared PostgreSQL connection pool used by all API routes.

import postgres from "postgres"

const sql = postgres(process.env.DATABASE_URL!, {
  max: 10,              // max simultaneous connections
  idle_timeout: 30,     // close idle connections after 30s
  connect_timeout: 10,  // fail if can't connect within 10s
})

export default sql
POOL
A connection pool keeps several persistent TCP connections to Postgres open and reuses them. Opening a new DB connection per HTTP request would be ~50–100ms overhead each time. With pooling, connections are already open — queries start immediately.
!
The ! after DATABASE_URL is a TypeScript non-null assertion — "I know this isn't undefined." If the .env file is missing this variable, the app crashes at startup with a confusing error.

Usage

import sql from "@/lib/db"

// Values auto-parameterised — no SQL injection possible
const rows = await sql`SELECT * FROM articles WHERE id = ${id}`

// sql() for raw SQL fragments (dynamic column names)
sql`INSERT ... ${sql`NOW()`}`

Converts a raw DB row (flat columns) into the rich Article TypeScript interface. The only place where DB column names meet the app's domain model.

Key transformations

HELPER
collectTrue(pairs) = pairs.filter(([flag]) => flag === true).map(([, value]) => value). Maps boolean flag arrays to typed value arrays. Used for sectors, stages, crisis domains, and frames.
// argmax: key with highest value
function argmax(scores: Partial<Record<string, number>>): string | null {
  let best = null, bestVal = -Infinity
  for (const [key, val] of Object.entries(scores)) {
    if (val != null && val > bestVal) { bestVal = val; best = key }
  }
  return best
}

// FRAME_THRESHOLD = 0.5
// frames[] = collectTrue([score >= 0.5, frameName]) — multi-label
// primaryFrame = argmax(frameScores)              — single best label

lib/useArticles.ts

A React hook that fetches all articles once and caches them in a module-level variable for the lifetime of the browser tab.

// Module-level — persists across component mounts/unmounts
let _cache: Article[] | null = null
let _promise: Promise<Article[]> | null = null

function fetchArticles(): Promise<Article[]> {
  if (_cache) return Promise.resolve(_cache)   // already loaded
  if (_promise) return _promise                   // in-flight — dedup
  _promise = fetch("/api/articles")
    .then(r => r.json())
    .then(data => { _cache = data; _promise = null; return data })
  return _promise
}
WHY
If 3 components call useArticles() simultaneously (overview page mounts multiple chart sections at once), all 3 get the same _promise — only one HTTP request fires. Once resolved, all future calls return _cache synchronously.
TRADE
No cache invalidation. If someone uploads an article via UploadPanel, the cache is stale until a page reload. React Query would handle this, but that's an external dependency the project chose to avoid.

The hook

export function useArticles() {
  // Start with cached data if available — avoids loading flash on re-mount
  const [articles, setArticles] = useState<Article[]>(_cache ?? [])
  const [loading, setLoading]   = useState(_cache === null)
  const [error, setError]       = useState<string | null>(null)
  // useEffect fetches if not cached
}

backend/main.py

The entire Python backend — model loading, text extraction, and classification — in one file.

POST /classify

@app.post("/classify")
def classify(req: ClassifyRequest):
    predictor = _get_predictor()
    if predictor is None:
        raise HTTPException(status_code=503)  # no checkpoint → graceful fail

    results = predictor.predict([req.text], batch_size=1, explain=True)
    r = results[0]
    frame_scores = {LABEL_MAP.get(k, k): v for k, v in r["probabilities"].items()}
    # LABEL_MAP renames "Responsibility" → "Attribution of Responsibility"
    explanation = json.loads(r.get("explanation", "{}"))
    # explanation = {wordIndex: attentionScore}
FLOW
The same Predictor class handles both frame and angle models, with different checkpoint paths. Angle model passes calibrations=None — no Platt calibration fitted yet.

POST /extract-text — LexisNexis detection

if "LexisNexis" in full:
    article_text = "\n".join(pages[1:])  # skip page 0 — metadata header
    body_m = re.search(
        r'\bBody\n(.+?)(?:\nClassification\b|\Z)',
        article_text, re.DOTALL
    )
    title_m = re.search(r'Page 1 of \d+\n(.+?)(?:\n|$)', article_text)
WHY
LexisNexis exports: page 0 is search metadata, page 1 starts the article, article body is delimited by "Body" on its own line. The regex extracts only the article text, stripping all LexisNexis metadata.

Text normalisation

def _normalize_body(text):
    PARA = "\x01"                               # temporary sentinel
    text = re.sub(r'\n{2,}', PARA, text)         # blank lines → sentinel
    text = re.sub(r'([.!?])\n', ..., text)       # sentence-end newline → sentinel
    text = re.sub(r'\n', ' ', text)             # remaining newlines → space
    text = text.replace(PARA, '\n\n')           # restore paragraph breaks
    return text.strip()

app/layout.tsx

Root layout — renders once and wraps every page. Loads fonts and renders the persistent header.

localFont() pattern

const playfairDisplay = localFont({
  variable: "--font-playfair",   // CSS var used in components
  src: [
    { path: "../node_modules/@fontsource/playfair-display/...",
      weight: "400", style: "normal" },
  ],
})
WHY
Fonts come from node_modules/@fontsource/* — the packages bundle the actual woff2 files. localFont() generates an optimised CSS @font-face and exposes a CSS variable. No Google Fonts CDN = no third-party request, works offline, no GDPR concern.
GOTCHA
All 6 font CSS variables are applied to <html> via className={fontVars}. If you add a component that uses var(--font-podkova) but don't add the font here, the variable won't exist at runtime.

Parallel classification trick

// Classification fires IMMEDIATELY when file is read,
// but save() only awaits it when the user clicks Save.

  .then(r => r.ok ? r.json() : null)
  .catch(() => null)

Theory & Core Concepts

The theoretical backbone of the project. These concepts are what the essay argues about — not just cited, but actively interrogated.

Agenda-Setting Theory

McCombs & Shaw (1972), McCombs (2004)

The media do not tell people what to think, but what to think about. By choosing which stories to cover and how prominently, media set the public agenda. In this project: keyword-based monitoring (what QuotaClimat already had) answers the agenda-setting question — how much climate is covered. The project moves one level deeper to ask how it is framed.

Framing Theory

Entman (1993)

Framing is selecting and salience — choosing which aspects of a perceived reality to make more prominent in a text, promoting a particular problem definition, causal interpretation, moral evaluation, or remedy. A frame is not what is covered; it is how what is covered is packaged for the reader.

Meso Level of Media Production

KEY
Three levels: macro (structural forces — ownership, politics, economy), meso (editorial decisions — what journalists and editors choose to write and how), micro (audience effects). The project targets meso because that is the only level NGOs and regulators can actually act on. They cannot change macro forces, and they cannot observe micro effects — but they can challenge editorial choices, which leave a trace in the text.

Semetko & Valkenburg (2000) — Five Generic Frames

FrameWhat it emphasises
Attribution of ResponsibilityWho or what is to blame / who should solve the problem
Human InterestA human face or emotional angle on the issue
ConflictDisagreement between individuals, groups, or institutions
MoralityMoral messages, prescriptions for behaviour, social norms
Economic ConsequencesFinancial implications for individuals, groups, or society
JOURNEY
The project started with Guenther et al. (2024)'s 14-frame scheme — richer, but categories overlapped too much to separate reliably. Only after watching it fail did the team narrow to Semetko & Valkenburg's 5. The essay is honest: the report presents this as a principled choice; the reality is they "reached the principled answer the long way."

Construct Validity

Cronbach & Meehl (1955)

The gap between a concept as theory defines it and the thing you can actually measure. A frame is clean as a theoretical construct and slippery as a measurement. This is the essay's through-line: every major difficulty — the typology choice, the discrepancy metric, the explanation feature, the angle classifier — was a construct validity problem, not a theory problem.

Krippendorff's Alpha (α)

INFO
A measure of inter-annotator reliability: how consistently do two (or more) annotators label the same text? Scale: 0 = no agreement, 1 = perfect agreement. Generally, α ≥ 0.8 is accepted; α ≥ 0.67 is tentatively acceptable. In this project: most frames reached acceptable levels, but Attribution of Responsibility — the dominant frame at ~62% of articles — had α = 0.28, indicating unreliable classification and systematic overprediction. The essay uses this not just as a classifier failure but as evidence that the category itself may not be recoverable from the text at scale.

LLM as Annotator

Törnberg (2023, 2024)

An LLM (here GPT, via API) can be a more consistent annotator than a human, because it applies the same criteria across thousands of articles without drifting. Humans drift — they fatigue, reinterpret criteria mid-task, and disagree. This is the theoretical justification for using an LLM to generate training labels (silver labels), rather than relying on human-only annotation. Törnberg (2024) also argues open-source annotators are best-practice for transparency and reproducibility — which is why the team started with an Ollama-hosted model before switching to GPT.

Knowledge Distillation

INFO
A technique where a large, capable model (the "teacher" — here GPT) generates labels, and those labels are used to train a smaller, faster model (the "student" — here RoBERTa). The student learns to approximate the teacher's behaviour at much lower inference cost. In this project, GPT labels articles → those labels train a cross-lingual RoBERTa classifier. The essay notes this is "knowledge distillation applied to frame labelling rather than topic classification, which it had been validated on before" — framed as a contribution.

Attention is not Explanation

Jain & Wallace (2019)

A well-known NLP paper arguing that attention weights inside a transformer model cannot be straightforwardly interpreted as explanations of why the model made a prediction. High attention on a word does not mean that word caused the output. The project uses attention scores for the word-highlight explanation feature — the essay concedes this is contested and should have been treated as a first-class problem, possibly with a separate dedicated model.

Wicked Problems

Rittel & Webber (1973)

A "wicked problem" has no clean definition, no agreed stopping rule, no right or wrong solution (only better or worse), and every attempt to solve it changes the problem. Used in the conclusion to describe what the CSSci programme is actually training for: not technical problems with known solutions but messy, value-laden, context-dependent interventions where being clever is not enough.

Intervention Decisions

The essay's evaluation of what the team built — what was right, what was weak, and why.

The Bring-Your-Own-Data Architecture

DEFEND
The essay's strongest defence of a technical decision. Instead of a hosted dashboard consuming a shared dataset, users bring their own licensed news corpus. This solved three problems at once: (1) copyright — no redistribution of licensed articles; (2) political exposure — each NGO runs the analysis on their own data and owns the conclusions; (3) scalability — no hosting/scaling burden on the team. Makes the tool "open-source-ready" so any NGO or journalist can run it on a corpus they've licensed themselves.

The Discrepancy-First Approach

CORE
Instead of just describing how articles are framed, the tool compares: frames vs sectors, outlets vs each other, media attention vs real GHG emissions per sector. The essay argues this is the "real academic contribution" because it "reframes meso-level framing analysis as comparative rather than descriptive and matches how our users already think." Coverage volume alone is not the lever; the gap between coverage and emissions share is.

14 Frames → 5 Frames: What happened

StageDecisionOutcome
StartGuenther et al. (2024) 14-frame typology, chosen for theoretical richnessCategories overlapped, classifier couldn't separate them reliably
Mid-projectLLM annotator: started with open-source model via OllamaNot strong enough — validated Mark's early concern
SwitchMoved to GPT API (hosted)Better annotation quality; cost ~€20 for a pilot that took weeks to reach
FinalSemetko & Valkenburg 5 framesAcceptable reliability for most; Attribution of Responsibility still α=0.28
LESSON
The essay's proposed fix: treat typology choice and classifier tractability as one joint decision, not sequential. Pilot several candidate schemes through one pipeline on small samples. Let what the classifier can actually separate have equal weight to what is theoretically elegant. A €20 GPT pilot would have told them in days what took weeks.

The Dashboard — Where the Essay is Least Confident

WEAK
Feedback was positive but on aesthetics ("how it looks"), not fit ("whether it changes what someone does on a Tuesday afternoon"). The user research was affirming and non-confronting — participants liked what was shown and suggested little new. The essay diagnoses this as possible confirmation bias from the novelty of the tool. No deep-dive into actual user workflows was done. A few walk-throughs with real tasks would have been more valuable than additional polish.

The Explanation Feature

CRITIQUE
Highlights words the model's attention scores associate with a frame. Problem: the model learns from token-level statistical patterns; a human reads framing against the whole media landscape. A word the model attends to can be the right signal for the model and meaningless to a person trying to challenge coverage. This is the Jain & Wallace (2019) problem. The essay's honest answer: "The mistake was not the feature but how little attention we gave it." Time crunch is why it wasn't treated as a first-class problem.

The Angle Classifier

INFO
Angles (Health, Economics, Jobs, Politics, Geopolitics, Purchasing Power) are what the partner actually reasons in day-to-day. Including them was right — leaving them out would make the tool less useful. The critique: hand-labelling for training data was postponed too long (same pattern as the 14-frame detour: deliberating on theory before testing against labelled data). The time this ate left the angle classifier and the explanation feature under-resourced.

The Nexis Scraper — Technical Detail

DETAIL
Nexis writes the first page of results into a page array that, on later pages, still holds the previous page's data — so parsing the DOM silently returns stale results. The accepted date format also varied with the interface language. Duplicates were constant. Query behaviour was unreliable, creating downstream integrity problems that required repair scripts. The essay describes this as a new skill: "building a robust scraper against a hostile source."

Ownership and Role Deference

Key teamwork lesson #1

Multiple points where Mark had a firm view on something outside his lane (modelling, typology, design, report). Pattern each time: voiced the concern, then let the person who owned that area decide — even when he would have gone the other way. The lesson: "the difference between caring about the right outcome and needing to be the one who delivers it." Trusting someone else to own work you care about is a learnable skill. The cost is sometimes weeks of rework; the benefit is a functioning team and freed attention.

EXAMPLE
He raised a concern early that the open-source model might not be strong enough. Max (the ML lead) said it would be fine. Mark conceded. The concern turned out to be correct — but conceding was the right team process. The essay doesn't frame this as "I was right"; it frames it as a learning about when to push and when to defer.

Process Friction — Notion

INFO
The team ran a heavy Notion system suited to a longer project. On their timeline — especially after the partner change created time pressure — it felt like friction. The lesson: process tools should match the project's actual timeline and pace. Would push for something lighter next time.

Communication Under Stress

Key teamwork lesson #2

Capstone was long and intense. Several team members dealing with personal difficulty alongside the project. There was a stretch where the strain showed on calls. Mark's approach: pick up tension rather than let it fester, follow up with people who were struggling, be honest about his own bandwidth. The reflection: "conflict resolution is not separate from the work; it is part of it."

What Changed for Mark Professionally

HONEST
Many obvious answers don't apply — he already worked as a forward-deployed engineer, been through startups, talks to non-technical people, runs his own business. What actually shifted: caring more about the ethical and scientific side of what he builds; better at finding common ground with researchers and academics (not commercially minded, brilliant in ways the commercial world rarely rewards). The part he wants to carry forward: more time building alongside people who are in it for something other than a market.

Engineering Value vs. Research Contribution

KEY
The report's headline is the discrepancy-first analytical approach and two "firsts" (first LLM frame labelling of a French environmental corpus; knowledge distillation applied to frame labelling). Mark's personal pride is in something more mundane: building an extensible platform someone else can pick up and run. His argument: a tool that lowers the cost of comparative framing analysis enables more of it to get done, on more corpora, so patterns that would go unexamined get a chance to surface as research questions. Indirect academic value through platform provision.
